# Workflows: theory draft

Harvested from PostHog/posthog (`products/workflows`, `nodejs/src/cdp/services/hogflows`) since 2026-03-01: review comments, agent corrections, and written rules.
Each rule links where it came up. The quotes, what was checked in the code, and the full evidence live in `rules.json`.
Levels say how a rule holds today: `review-only` (a reader), `documented` (a doc says so), `linted` (CI fails), `structural` (the wrong code cannot be written).
This is a draft for the team to argue with. Nothing here is agreed yet.

## Vocabulary

**Workflow**:
The user-facing name for one automation: a directed graph of actions wired by edges with exactly one trigger action. Stored as a HogFlow row.
_Avoid_: hog flow, hogflow, campaign, flow

**HogFlow**:
The internal code and model name of a workflow (HogFlow, hog_flow, /hog_flows API). Appears only in code identifiers and routes, never in UI copy, MCP descriptions or skills.
_Avoid_: workflow (in code identifiers)

**Action**:
One id-addressed node of the workflow graph. Its type comes from the closed set SUPPORTED_ACTION_TYPES (trigger, function, function_email, function_sms, function_push, delay, wait_until_condition, wait_until_time_window, conditional_branch, random_cohort_branch, exit). The editor calls it a step.
_Avoid_: hog function, task, node (outside the canvas)

**Edge**:
A directed link from one action to the next. A continue edge is the fall-through or timeout path; a branch edge carries an index into the source action's conditions or cohorts.
_Avoid_: connection, link

**Trigger**:
The single trigger action that starts every run. Its config.type is the trigger type (event, batch, schedule, webhook, manual, tracking_pixel, data-warehouse-table, data-warehouse-view, internal-event). The top-level trigger field is derived from it and read-only.
_Avoid_: entry point, event (for the trigger itself)

**Row-scoped trigger**:
A trigger whose runs have no PostHog person: data-warehouse-table, data-warehouse-view and internal-event (Slack, GitHub). Person-dependent actions are rejected on these workflows.
_Avoid_: person-less workflow, DWH workflow

**Status**:
The lifecycle state of the live workflow row: draft, active or archived. Changed by explicit lifecycle actions (enable, disable, archive).
_Avoid_: draft (when meaning staged changes)

**Staged draft**:
Pending content edits held in the draft column of an active workflow. Nothing reaches people until it is published or discarded.
_Avoid_: draft status, unsaved changes

**Publish**:
Promote the staged draft to the live row after strict revalidation and a publish-impact preview. Bumps version and appends a revision.
_Avoid_: save, deploy

**Revision**:
An append-only snapshot of a workflow's live content at one version. Restoring a revision copies it into the staged draft; workers never read revisions.
_Avoid_: history entry, backup

**Version**:
The integer on the live workflow that identifies which content produced a metric. Metrics are keyed <flow id>/<version> under app_source hog_flow_version.
_Avoid_: revision id

**Run**:
One execution of a workflow for one person or row, persisted as an invocation (Cyclotron job) that can park on a delay or wait and wake later.
_Avoid_: job, execution, instance

**Batch**:
A one-off dispatch of a batch-trigger workflow to a person audience defined by person properties or cohorts. Broadcast is the product surface built on batch workflows.
_Avoid_: blast, campaign send

**Schedule**:
A recurring cadence (rrule, timezone, variables) attached to a batch or schedule workflow; the scheduler reads the live trigger when it fires.
_Avoid_: cron, scheduled run

**Blast radius**:
The audience preview for a batch dispatch. It returns the recipient count and a confirm token bound to the stored trigger filters that programmatic dispatch must present.
_Avoid_: audience count

**Conversion**:
A goal (events and property filters within a window) counted at most once per run and credited to the version that sent the message.
_Avoid_: goal event, exit event

**Function template**:
A Hog template (template_id) that a function step runs, from nodejs/src/cdp/templates. Email, SMS and push steps use the fixed literals template-email, template-twilio and template-native-push.
_Avoid_: email template, workflow template

**Email template**:
A saved library message design referenced by template_uuid. Its body is snapshotted into the step at save; later template edits do not propagate.
_Avoid_: template_id, function template

**Secret input**:
A function-step or trigger input marked secret in its template schema. It is stored encrypted in encrypted_inputs and returned as {secret: true}.
_Avoid_: credential field, api key input

## Guarantees

- **`row-scoped-triggers-reject-person-steps`**: Workflows with a row-scoped trigger reject person-dependent steps and exit only at the end. _Workflow API; structural → structural; high confidence; 3 occurrences, 2 independent reviewers: [pr#59468 meikelmosby](https://github.com/PostHog/posthog/pull/59468#discussion_r3347822341), [pr#84460 mayteio](https://github.com/PostHog/posthog/pull/84460#discussion_r3895035867), [graph-schema.md L76](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/references/graph-schema.md#L76)._
- **`closed-type-sets-have-one-home`**: Action types, trigger types, and the person-dependent and row-scoped sets are declared once and checked for parity across Django, the Node worker and the editor. _Step and trigger registry; documented → linted; medium confidence; 3 occurrences, 1 independent reviewer: [pr#91572 mayteio](https://github.com/PostHog/posthog/pull/91572#discussion_r3894329629), [pr#62649 mayteio](https://github.com/PostHog/posthog/pull/62649#discussion_r3429112588), [graph-schema.md L40](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/references/graph-schema.md#L40)._
- **`graph-structure-validated-on-every-write`**: Every graph write passes validate_graph: unique action ids, one trigger, real edge endpoints, in-range branch indexes and a resolution edge on every wait. _Workflow API; documented → structural; high confidence; 5 occurrences, 3 independent reviewers: [pr#62649 mayteio](https://github.com/PostHog/posthog/pull/62649#discussion_r3429112580), [pr#63583 dmarchuk](https://github.com/PostHog/posthog/pull/63583#discussion_r3422283457), [pr#72913 mayteio](https://github.com/PostHog/posthog/pull/72913#discussion_r3632135646), [pr#49947 sortafreel](https://github.com/PostHog/posthog/pull/49947#discussion_r2900710261), and 1 more._
- **`server-compiles-all-bytecode`**: Only the server compiles bytecode; client-supplied bytecode is discarded on every write path. _Workflow API; documented → structural; high confidence; 4 occurrences, 0 independent reviewers: [pr#57847 dmarchuk](https://github.com/PostHog/posthog/pull/57847#discussion_r3335658853), [pr#63545 mayteio](https://github.com/PostHog/posthog/pull/63545#discussion_r3414126437), [pr#62649 ghost (bot)](https://github.com/PostHog/posthog/pull/62649#pullrequestreview-4516516322), [graph-schema.md L190](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/references/graph-schema.md#L190)._
- **`active-workflows-change-only-through-publish`**: Content edits to an active workflow stage a draft; only publish promotes it, after strict revalidation. _Draft and revision store; documented → structural; high confidence; 5 occurrences, 1 independent reviewer: [pr#81905 mayteio](https://github.com/PostHog/posthog/pull/81905#discussion_r3776904952), [pr#70823 mayteio](https://github.com/PostHog/posthog/pull/70823#discussion_r3585946833), [pr#60388 mayteio](https://github.com/PostHog/posthog/pull/60388#discussion_r3316614760), [pr#81323 dmarchuk](https://github.com/PostHog/posthog/pull/81323#pullrequestreview-4914901622), and 1 more._
- **`stale-writes-fence-on-the-loaded-stamp`**: Every write to workflow content fences on the stamp the writer loaded, bumps the stamp it changes, and returns 409 when the row moved. _Draft and revision store; review-only → structural; high confidence; 4 occurrences, 0 independent reviewers: [pr#81323 mayteio](https://github.com/PostHog/posthog/pull/81323#discussion_r3760280129), [pr#101505 luke-belton](https://github.com/PostHog/posthog/pull/101505#discussion_r4025420816), [pr#85239 mayteio](https://github.com/PostHog/posthog/pull/85239#discussion_r3812983888), [pr#105625 dmarchuk](https://github.com/PostHog/posthog/pull/105625#discussion_r4107381109)._
- **`secrets-masked-in-every-representation`**: Secret inputs are encrypted at rest and masked in every outward representation: actions, trigger, draft, activity log, log lines and agent context. _Workflow API; review-only → linted; high confidence; 4 occurrences, 1 independent reviewer: [pr#72913 dmarchuk](https://github.com/PostHog/posthog/pull/72913#discussion_r3637293575), [pr#80639 mayteio](https://github.com/PostHog/posthog/pull/80639#discussion_r3750861704), [pr#70823 mayteio](https://github.com/PostHog/posthog/pull/70823#discussion_r3586204077), [pr#83804 greptile-apps (bot)](https://github.com/PostHog/posthog/pull/83804#discussion_r3802613616)._
- **`child-rows-take-team-from-their-workflow`**: Rows that hang off a workflow take team_id from the workflow, and cross-team isolation is asserted through the API. _Draft and revision store; review-only → structural; high confidence; 6 occurrences, 3 independent reviewers: [pr#72572 mayteio](https://github.com/PostHog/posthog/pull/72572#discussion_r3623789207), [pr#72543 meikelmosby](https://github.com/PostHog/posthog/pull/72543#discussion_r3622844774), [pr#68133 mayteio](https://github.com/PostHog/posthog/pull/68133#pullrequestreview-4745189470), [pr#72573 dmarchuk](https://github.com/PostHog/posthog/pull/72573#discussion_r3629296112), and 2 more._
- **`dispatch-requires-a-previewed-audience`**: Every dispatch to a batch audience, from any caller, first previews the audience and presents the confirm token bound to it. _Batch and schedule dispatcher; documented → structural; medium confidence; 5 occurrences, 0 independent reviewers: [pr#73225 mayteio](https://github.com/PostHog/posthog/pull/73225#discussion_r3643941753), [pr#61001 mayteio](https://github.com/PostHog/posthog/pull/61001#discussion_r3341385166), [pr#93383 mayteio](https://github.com/PostHog/posthog/pull/93383#discussion_r3916725241), [SKILL.md L22](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/SKILL.md#L22), and 1 more._
- **`configs-are-typed-unions`**: Trigger and step configs are typed as discriminated unions end to end, so an unsupported shape is a compile error, not a runtime surprise. _Step and trigger registry; review-only → structural; medium confidence; 3 occurrences, 1 independent reviewer: [pr#100259 gantoine](https://github.com/PostHog/posthog/pull/100259#discussion_r4006503486), [pr#103843 Silthus](https://github.com/PostHog/posthog/pull/103843#discussion_r4069025491), [pr#57470 pauldambra](https://github.com/PostHog/posthog/pull/57470#discussion_r3182447995)._
- **`template-ids-resolve-and-fixed-channels-are-server-checked`**: Every template_id a step references resolves to a real Hog template; email, SMS and push steps carry their channel's literal, inferred and checked by the server. _Step and trigger registry; documented → linted; high confidence; 4 occurrences, 0 independent reviewers: [pr#78208 mayteio](https://github.com/PostHog/posthog/pull/78208#discussion_r3720060567), [pr#89923 meikelmosby](https://github.com/PostHog/posthog/pull/89923#discussion_r3880399581), [CONTRIBUTING.md L348](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/CONTRIBUTING.md#L348), [graph-schema.md L134](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/references/graph-schema.md#L134)._

## Boundaries

- **`custom-actions-declare-scopes-and-object-access`**: Every custom hog_flow action declares its API scopes, adds person:read or group:read when it exposes or dispatches to people, and filters per-workflow data by object access. _Workflow API; review-only → linted; high confidence; 5 occurrences, 1 independent reviewer: [pr#73522 mayteio](https://github.com/PostHog/posthog/pull/73522#discussion_r3646021418), [pr#61655 dmarchuk](https://github.com/PostHog/posthog/pull/61655#discussion_r3376284096), [pr#68133 meikelmosby](https://github.com/PostHog/posthog/pull/68133#discussion_r3620011080), [pr#83342 mayteio](https://github.com/PostHog/posthog/pull/83342#discussion_r3803370096), and 1 more._
- **`registry-owns-trigger-and-step-types`**: A new trigger or step type lives in its own registry file, registered by side-effect import, and needs no change to workflowLogic.ts. _Step and trigger registry; documented → linted; high confidence; 4 occurrences, 2 independent reviewers: [pr#47035 meikelmosby](https://github.com/PostHog/posthog/pull/47035#discussion_r2877422332), [pr#91466 mayteio](https://github.com/PostHog/posthog/pull/91466#discussion_r3894062146), [pr#59468 Gilbert09](https://github.com/PostHog/posthog/pull/59468#discussion_r3349112235), [CONTRIBUTING.md L78](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/CONTRIBUTING.md#L78)._

## Caveats

- Web-builder drafts validate leniently while programmatic callers (MCP, raw API) validate strictly (_should_validate_strictly, hog_flow.py L850). An invalid config can sit in a web draft until publish or enable revalidates it. ([pr#81905 mayteio](https://github.com/PostHog/posthog/pull/81905#discussion_r3776904952))
- Graph validation is a hard error only on the /graph patch endpoint. Create and full PATCH only log structural errors, because existing active workflows already carry broken graphs. ([pr#63583 mayteio](https://github.com/PostHog/posthog/pull/63583#discussion_r3427963910), [pr#63583 mayteio](https://github.com/PostHog/posthog/pull/63583#discussion_r3427964062))
- A decrypt failure on encrypted_inputs is fail-open: the flow runs without its secrets (parity with HogFunction), and only the cdp_hogflow_encrypted_inputs_decrypt_failed counter signals it. ([pr#72913 mayteio](https://github.com/PostHog/posthog/pull/72913#discussion_r3632133931), [pr#72913 dmarchuk](https://github.com/PostHog/posthog/pull/72913#discussion_r3637166337))
- Only agent callers (MCP, PostHog AI) must present the blast-radius confirm token. The web builder keeps its own confirm UI and headless API keys dispatch without one. ([pr#73225 mayteio](https://github.com/PostHog/posthog/pull/73225#discussion_r3643942550))
- Workflow views still live in backend/api/, so the 'routes must only import presentation' import-linter contract carries four ignore_imports lines for workflows. ([doc:pyproject.toml L740](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/pyproject.toml#L740))
- Counter metrics cannot attribute a bounce, open or complaint to its send, so time-windowed rates are approximations that can exceed 100% at window edges. ([pr#74762 meikelmosby](https://github.com/PostHog/posthog/pull/74762#discussion_r3682801318), [pr#78136 mayteio](https://github.com/PostHog/posthog/pull/78136#discussion_r3719551492))
- The batch audience cap is a dispatch-time pre-gate. An email step added to an already queued batch skips it; only the send-time tier buckets still apply. ([pr#89923 meikelmosby](https://github.com/PostHog/posthog/pull/89923#discussion_r3880168522))
- Durations clamp silently per unit, and a delay_until date is re-read on every wake, so a date that moves closer does not wake a parked run earlier. ([graph-schema.md L167](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/references/graph-schema.md#L167), [graph-schema.md L191](https://github.com/PostHog/posthog/blob/57ca357730843205c2d659098ac8e4c5e07a6698/products/workflows/skills/building-workflows/references/graph-schema.md#L191))
- The HogFlow post_save worker reload fires inside the transaction (only post_delete defers to on_commit), so management commands defer the reload themselves. ([pr#85239 mayteio](https://github.com/PostHog/posthog/pull/85239#discussion_r3812984346))
