# runTests on a scratch worktree of PostHog upstream/master 57ca357 (the base from #73)

The workspace's uv.lock differs from ~/dev/posthog's, so the borrowed venv would not match the base.
runTests now syncs a venv of the workspace's own first:
  env -u VIRTUAL_ENV UV_PROJECT_ENVIRONMENT=<workspace>/.venv GIT_CONFIG_GLOBAL=/dev/null <flox uv> sync --quiet --frozen
and then runs <workspace>/.venv/bin/pytest. With an identical lock it borrows ~/dev/posthog/.flox/cache/venv as before.
~/dev/posthog's venv is never written (its bin/pytest still has mtime Sep 21 after these runs).

GIT_CONFIG_GLOBAL=/dev/null applies to the sync only. Without it, uv's git fetch of pytest-split hit the same
SSH rewrite as #86 (sign_and_send_pubkey: signing failed ... Permission denied (publickey)). Now it fetches, and
the build of PostHog's pytest-split fork at v0.11.0-posthog.7 fails: uv 0.12.13 (the version PostHog's flox env
and CI pin) rejects the wheel's metadata. That is an upstream environment problem, and the run is not run.
